Session 1 — Batch 1 (UdemyQ01 & Q02)
1
What does typeof null return?
console.log(typeof null); // "object"
Answer: "object"
A long-standing JavaScript bug. null is a primitive, not an object, but typeof null returns "object" due to a legacy implementation quirk that was never fixed to avoid breaking existing code.
💡 To check for null, use value === null — never rely on typeof.
2
What is the difference between == and ===?
console.log(1 == "1"); // true — loose, coerces string to number console.log(1 === "1"); // false — strict, type mismatch console.log(0 == false); // true console.log("" == false); // true
Answer
== performs type coercion before comparing. === checks type AND value — no coercion. Always prefer ===.
💡 The only acceptable use of ==: value == null (catches both null and undefined).
3
What does var hoisting produce here?
console.log(x); // undefined — declaration hoisted, not value var x = 5; console.log(x); // 5
Answer: undefined then 5
var declarations are hoisted to the top of their scope, but the assignment stays in place. The variable exists but is undefined until the assignment line runs.
💡 let and const are also hoisted but stay in the Temporal Dead Zone — accessing them early throws a ReferenceError.
4
What is an IIFE?
(function() { var secret = 42; console.log("Runs immediately:", secret); })(); // () at the end invokes it instantly
Answer
Immediately Invoked Function Expression — a function that runs the moment it's defined. Used to create a private scope and avoid polluting the global namespace.
💡 Pre-ES6 modules used IIFEs heavily. Today you'd use ES modules or block scope with let.
5
Explain this closure — what does counter() return each call?
function makeCounter() { let count = 0; return () => ++count; } const counter = makeCounter(); console.log(counter()); // 1 console.log(counter()); // 2 console.log(counter()); // 3
Answer: 1 2 3
The inner arrow function closes over count. Each call increments and returns the same count variable — it persists in memory as long as counter holds a reference to the inner function.
6
What does Promise.all() return, and in what order?
Promise.all([ Promise.resolve("A"), Promise.resolve("B"), Promise.resolve("C") ]).then(results => console.log(results)); // ["A", "B", "C"] — order preserved, even if B resolves first
Answer: ["A","B","C"]
Returns a single Promise that resolves with an array of all results in input order — regardless of resolution speed. If any Promise rejects, the whole thing rejects immediately.
💡 Use Promise.allSettled() if you need results even when some fail.
7
How does array destructuring swap work?
let a = 1, b = 2; [a, b] = [b, a]; console.log(a, b); // 2 1
Answer: 2 1
The right-hand side creates a temporary array [2, 1], then destructuring assigns those values in order to a and b. No temp variable needed.
💡 Classic interview trick — clean, idiomatic JS swap.
8
Why is NaN === NaN false?
console.log(NaN === NaN); // false — by spec console.log(Number.isNaN(NaN)); // true — correct test console.log(isNaN("hello")); // true — older, coerces first
Answer: false
By IEEE 754 spec, NaN is the only value not equal to itself. Use Number.isNaN() (preferred) or Object.is(val, NaN) to detect it.
⚠️ Hall of Shame
The old isNaN() coerces strings first — isNaN("hello") is true. Always use Number.isNaN().
9
What does spread copy — and what does it NOT copy?
const original = { x: 1, nested: { y: 2 } }; const copy = { ...original }; copy.x = 99; copy.nested.y = 99; console.log(original.x); // 1 — primitive, safe console.log(original.nested.y); // 99 — shared reference!
Answer
Spread performs a shallow copy — top-level primitives are duplicated, but nested objects are still shared by reference. Deep copy requires structuredClone().
10
How do you catch errors with async/await?
async function fetchData() { try { const res = await fetch("/api/data"); const data = await res.json(); return data; } catch (err) { console.error("Failed:", err.message); } }
Answer
Wrap await calls in a standard try/catch. The rejected Promise throws an error that the catch block receives — just like synchronous exception handling.
💡 Alternatively, chain .catch() on the returned promise from the async function.
11
What is the difference between for…of and for…in?
const arr = ["a", "b", "c"]; for (const val of arr) { console.log(val); } // "a" "b" "c" — VALUES for (const key in arr) { console.log(key); } // "0" "1" "2" — KEYS (strings!) const obj = { a: 1, b: 2 }; for (const key in obj) { console.log(key); } // "a" "b"
Answer
for…of iterates values of any iterable (arrays, strings, Sets, Maps). for…in iterates enumerable property keys — use it on objects, avoid it on arrays (includes inherited props).
💡 Never use for…in on arrays. Use for…of or .forEach() instead.
12
How does the prototype chain work?
const animal = { breathes: true }; const dog = Object.create(animal); dog.barks = true; console.log(dog.barks); // true — own property console.log(dog.breathes); // true — found on prototype console.log(dog.flies); // undefined — not found anywhere
Answer
When a property isn't found on an object, JS looks up the [[Prototype]] chain until it finds the property or reaches null (the end of the chain). This is the foundation of JS inheritance.
13
What does typeof undefined return?
console.log(typeof undefined); // "undefined" console.log(typeof "hello"); // "string" console.log(typeof 42); // "number" console.log(typeof true); // "boolean" console.log(typeof {}); // "object" console.log(typeof []); // "object" — arrays are objects! console.log(typeof function(){}); // "function"
Answer: "undefined"
typeof is one of the few operators safe to use on an undeclared variable. Arrays return "object" — use Array.isArray() to check for arrays.
💡 The seven typeof results: "undefined", "boolean", "number", "bigint", "string", "symbol", "function", "object".

What does Array.from() do?
Array.from("hello"); // ["h","e","l","l","o"] Array.from({ length: 3 }, (_, i) => i); // [0, 1, 2] Array.from(new Set([1, 2, 2, 3])); // [1, 2, 3] — deduped // Converts any iterable or array-like to a real Array
Answer
Creates a new Array from an iterable or array-like object (NodeList, arguments, Set, Map, string). Accepts an optional map function as the second argument.
15
What does optional chaining (?.) do?
const user = { address: { city: "Hagerstown" } }; console.log(user?.address?.city); // "Hagerstown" console.log(user?.phone?.number); // undefined — no throw // Without ?: accessing undefined.number would throw TypeError
Answer
Short-circuits and returns undefined if the left side is null or undefined, instead of throwing a TypeError. Saves deeply nested null checks.
💡 Combine with ??: user?.name ?? "Guest" for safe access with fallback.
16
What does the nullish coalescing operator (??) do?
console.log(null ?? "default"); // "default" console.log(undefined ?? "default"); // "default" console.log(0 ?? "default"); // 0 — 0 is NOT nullish console.log("" ?? "default"); // "" — empty string is NOT nullish // vs || : returns right side for ANY falsy value
Answer
Returns the right-hand value only when the left side is null or undefined (nullish). Unlike ||, it does NOT treat 0, "", or false as missing.
💡 Use ?? when 0 or empty string are valid values. Use || only when you want to fall back on any falsy value.
17
What is the difference between Map and Object?
const map = new Map(); map.set(42, "number key"); // any type as key map.set({}, "object key"); // objects as keys too map.set("name", "Tom"); console.log(map.size); // 3 — built-in size console.log(map.get("name")); // "Tom" // Map preserves insertion order // Object keys are always strings or Symbols
Answer
Map keys can be any type; Object keys are always strings or Symbols. Map has a built-in .size property, preserves insertion order reliably, and has no prototype-inherited properties to worry about.
💡 Use Map when keys aren't strings, when you need to count entries, or when key order matters critically.
18
What is a WeakMap?
let user = { name: "Tom" }; const wm = new WeakMap(); wm.set(user, { lastSeen: Date.now() }); console.log(wm.get(user)); // { lastSeen: ... } user = null; // original object unreferenced // Entry is eligible for garbage collection — no memory leak // WeakMap is NOT iterable — no .size, no .forEach
Answer
WeakMap holds weak references to its object keys — when the key object is garbage collected, the entry disappears automatically. Perfect for storing metadata about objects without preventing GC.
💡 WeakMap keys must be objects. It has no .size and isn't iterable — you can't list its entries. Use it for private data or caches tied to object lifetimes.

What is a generator function?
function* count() { yield 1; yield 2; yield 3; } const gen = count(); console.log(gen.next()); // { value: 1, done: false } console.log(gen.next()); // { value: 2, done: false } console.log(gen.next()); // { value: 3, done: false } console.log(gen.next()); // { value: undefined, done: true }
Answer
A function that can pause (yield) and resume execution. Returns a Generator object. Each .next() call runs until the next yield and returns { value, done }.
💡 Generators are great for lazy sequences, infinite ranges, and implementing custom iterators.

What does the Proxy object do?
const handler = { get(target, key) { return key in target ? target[key] : `No key: ${key}`; } }; const proxy = new Proxy({ name: "Tom" }, handler); console.log(proxy.name); // "Tom" console.log(proxy.age); // "No key: age"
Answer
Proxy intercepts and customizes fundamental operations on an object (get, set, delete, etc.) using traps. Used for validation, logging, default values, and reactive frameworks.
💡 Vue 3 uses Proxy under the hood for its reactivity system.

What is Symbol.iterator?
const range = { from: 1, to: 3, [Symbol.iterator]() { let cur = this.from; const end = this.to; return { next: () => cur <= end ? { value: cur++, done: false } : { value: undefined, done: true } }; } }; for (const n of range) console.log(n); // 1 2 3
Answer
A well-known Symbol that defines how an object is iterated. Implement it to make any object work with for…of, spread, and destructuring.
💡 Arrays, Strings, Maps, Sets all implement Symbol.iterator natively. You're implementing the same protocol.

What are tagged template literals?
function highlight(strings, ...values) { return strings.reduce((result, str, i) => result + str + (`<b>${values[i] ?? ""}</b>`), ""); } const name = "Tom", role = "Dev"; console.log(highlight`Hello ${name}, you are a ${role}`); // "Hello <b>Tom</b>, you are a <b>Dev</b>"
Answer
A function placed before a template literal receives the string parts and interpolated values as separate arguments. Used in styled-components, GraphQL's gql, sanitization, and i18n.
💡 strings is always one element longer than values. That's why values[i] ?? "" is needed for the last string piece.

What do Object.keys(), Object.values(), Object.entries() return?
const obj = { a: 1, b: 2, c: 3 }; Object.keys(obj); // ["a", "b", "c"] Object.values(obj); // [1, 2, 3] Object.entries(obj); // [["a",1], ["b",2], ["c",3]] // Transform objects with entries + fromEntries: Object.fromEntries( Object.entries(obj).map(([k, v]) => [k, v * 2]) ); // { a: 2, b: 4, c: 6 }
Answer
All three return arrays of the object's own enumerable properties. The keys/values/entries combo with Object.fromEntries() is the idiomatic way to transform objects.

What is currying?
const add = a => b => a + b; const add5 = add(5); // partial application — returns fn console.log(add5(3)); // 8 console.log(add(2)(3)); // 5 — all args at once
Answer
Currying transforms a function with multiple arguments into a chain of single-argument functions. Enables partial application — pre-fill some arguments and get a specialized function back.
💡 Used heavily in functional programming. Libraries like Ramda and lodash/fp curry automatically.

What is memoization?
function memoize(fn) { const cache = new Map(); return (...args) => { const key = JSON.stringify(args); if (cache.has(key)) return cache.get(key); const result = fn(...args); cache.set(key, result); return result; }; }
Answer
Caching the results of expensive function calls and returning the cached value on repeat calls with the same arguments. Trades memory for speed — classic dynamic programming optimization.
💡 Only effective for pure functions (same input always produces same output, no side effects).

Implement a simple event emitter pattern.
class EventEmitter { constructor() { this.events = {}; } on(event, cb) { (this.events[event] ||= []).push(cb); } emit(event, ...args) { (this.events[event] || []).forEach(cb => cb(...args)); } } const ee = new EventEmitter(); ee.on("data", msg => console.log("Got:", msg)); ee.emit("data", "hello"); // Got: hello
Answer
The pub/sub pattern — listeners subscribe to named events; the emitter notifies all listeners when an event fires. Node.js's built-in EventEmitter follows this pattern.
💡 Real-world use: decoupling components. The emitter doesn't know who's listening — listeners don't know who emits.

What is the difference between debounce and throttle?
// DEBOUNCE: fires AFTER a quiet period function debounce(fn, ms) { let timer; return (...args) => { clearTimeout(timer); timer = setTimeout(() => fn(...args), ms); }; } // THROTTLE: fires AT MOST once per interval // Use debounce for: search input, resize, validation // Use throttle for: scroll handlers, game loops, mousemove
Answer
Debounce: waits until events stop, then fires once. Throttle: fires at a fixed rate regardless of how many events occur. Both reduce how often a function runs under rapid input.
💡 Debounce = "wait until they stop typing." Throttle = "fire at most once per 100ms no matter what."

What is the difference between microtasks and macrotasks?
console.log("sync 1"); setTimeout(() => console.log("macrotask"), 0); Promise.resolve().then(() => console.log("microtask")); console.log("sync 2"); // Output: "sync 1", "sync 2", "microtask", "macrotask"
Answer
Microtasks (Promises, queueMicrotask) run after the current call stack empties, before the next macrotask. Macrotasks (setTimeout, setInterval, I/O) run one per event loop iteration.
💡 Priority: call stack → all microtasks → one macrotask → all microtasks → one macrotask…

What do flat() and flatMap() do?
[1, [2, [3, [4]]]].flat(); // [1, 2, [3, [4]]] — depth 1 [1, [2, [3, [4]]]].flat(Infinity); // [1, 2, 3, 4] [1, 2, 3].flatMap(x => [x, x * 2]); // [1, 2, 2, 4, 3, 6] — map then flatten one level
Answer
flat(depth) flattens nested arrays up to the specified depth (default 1). flatMap(fn) maps then flattens one level — equivalent to .map(fn).flat() but more efficient.
💡 flatMap is useful for producing zero, one, or multiple output elements per input — just return an array from the callback.
30
What do the logical assignment operators do?
let a = null; a ??= "default"; // a = "default" — assigned because a was nullish let b = 0; b ||= 42; // b = 42 — assigned because 0 is falsy let c = 5; c &&= c * 2; // c = 10 — assigned because c was truthy
Answer
??= assigns only if nullish. ||= assigns only if falsy. &&= assigns only if truthy. Short-circuit — the right side isn't evaluated if the condition isn't met.
💡 These avoid the verbose x = x ?? value pattern. Short-circuit evaluation means the right side only runs when needed.
31
What does Object.create() do?
const proto = { greet() { return `Hi, I'm ${this.name}`; } }; const obj = Object.create(proto); obj.name = "Tom"; console.log(obj.greet()); // "Hi, I'm Tom" console.log(Object.getPrototypeOf(obj) === proto); // true
Answer
Creates a new object with the specified object as its [[Prototype]]. The purest way to set up prototype-based inheritance without constructors or classes.
💡 Object.create(null) creates an object with NO prototype — no inherited methods like toString. Useful for pure hash maps.

What is the Reflect API?
const obj = { a: 1 }; Reflect.get(obj, "a"); // 1 — same as obj.a Reflect.set(obj, "b", 2); // true — sets obj.b = 2 Reflect.has(obj, "a"); // true — like "a" in obj Reflect.deleteProperty(obj, "a"); // true — like delete obj.a Reflect.ownKeys(obj); // ["b"] — own enumerable + symbol
Answer
Reflect provides methods for interceptable JavaScript operations, mirroring Proxy traps. Used alongside Proxy to forward operations to the original target correctly.
💡 Reflect.get(target, key, receiver) is more correct than target[key] inside a Proxy because it handles inheritance chains properly.

What does structuredClone() do?
const original = { name: "Tom", scores: [95, 87], date: new Date() }; const clone = structuredClone(original); clone.scores.push(100); console.log(original.scores); // [95, 87] — unchanged! // Also handles: Date, Map, Set, RegExp, ArrayBuffer // Does NOT handle: functions, class instances, DOM nodes
Answer
Native deep clone — creates a fully independent copy, including nested objects. Handles Date, Map, Set, ArrayBuffer. Replaces the JSON.parse(JSON.stringify()) hack for most cases.
💡 Available in all modern browsers and Node.js 17+. Still can't clone functions or DOM nodes.

What is dynamic import()?
// Static import — always loaded at startup: import utils from "./utils.js"; // Dynamic import — loads on demand, returns a Promise: async function loadChart() { const { Chart } = await import("./chart.js"); new Chart(canvas); } // Load only when the user clicks a button, etc.
Answer
Loads a module asynchronously at runtime — returns a Promise. Used for code-splitting: don't pay for code until it's needed. Bundlers (Vite, Webpack) split these into separate chunks automatically.
💡 The expression form import(path) allows dynamic paths — the static form does not.

How do you cancel a fetch request?
const controller = new AbortController(); fetch("/api/slow", { signal: controller.signal }) .then(res => res.json()) .catch(err => { if (err.name === "AbortError") console.log("Request cancelled"); }); // Cancel it: controller.abort();

What are named capture groups in regex?
const dateStr = "2024-12-25"; const re = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/; const { year, month, day } = dateStr.match(re).groups; console.log(year, month, day); // "2024" "12" "25"

Named capture groups ((?<name>...)) let you access matched parts by name instead of by index via the .groups property. Makes complex regex far more readable.
💡 Named groups also work in replace: str.replace(re, "$<year>/$<month>/$<day>").

What are the built-in JavaScript Error types?

How many times does this while loop run?
let i = 0; while (true) { i++; if (i === 3) break; } console.log(i); // 3
Answer: 3
The loop runs 3 times. i increments to 1, 2, 3 — when i === 3 the break exits the loop. while(true) is an intentional infinite loop that must be broken out of explicitly.

What is Event Bubbling?
// Click on <button> inside <div> inside <body> // Fires: button → div → body → html → document (upward) document.addEventListener('click', (e) => { console.log('Bubbled to document!'); }); // e.stopPropagation() — halts the bubble

💡 Use e.stopPropagation() to prevent the event from bubbling further. Foundation of event delegation.

What does this code demonstrate?
function createMultiplier(factor) { return function(number) { return number * factor; // factor lives in the closure }; } const double = createMultiplier(2); console.log(double(5)); // 10
Answer: 10
Closure — the inner function "remembers" factor even after createMultiplier has returned. double is a function with factor=2 baked in.

What is the purpose of setTimeout()?
setTimeout(() => { console.log("Hello after 2s"); }, 2000); console.log("I print first"); // synchronous, runs immediately // Output: "I print first", then "Hello after 2s"
Answer
Executes a callback function once after a specified delay (milliseconds). Non-blocking — the delay does not pause execution; synchronous code runs first.

Which function converts a string to an integer?
parseInt("5ee"); // 5 — reads until non-digit, stops parseInt("ee5"); // NaN — starts with non-digit, no parse parseInt("3.9"); // 3 — truncates, does NOT round parseInt("0xFF", 16); // 255 — radix argument parseFloat("3.9"); // 3.9 — keeps decimal
Answer: parseInt()
parseInt() parses from the left and stops at the first non-numeric character. Starts with a letter → NaN. Always pass a radix (10) to avoid octal surprises in older engines.
💡 parseInt("5abc") = 5, but parseInt("abc5") = NaN. The string must START with a digit.

What does concat() do — and what's the hidden trap?
const arr1 = [1, 2, { name: "Alice" }]; const arr2 = [3, 4]; const newArr = arr1.concat(arr2); console.log(newArr); // [1, 2, { name: "Alice" }, 3, 4] console.log(arr1); // [1, 2, { name: "Alice" }] — unchanged // ⚠️ But objects are shared by reference: newArr[2].name = "Bob"; console.log(arr1[2].name); // "Bob" — both arrays point to same object
Answer
concat() creates a new array — the container is new. But nested objects are shallow-copied: both arrays hold a reference to the same object.
⚠️ Shallow Copy Trap
Changing a primitive in newArr is safe. Mutating an object nested inside it affects the original too.

What is CORS?
// Cross-Origin Resource Sharing // Browser blocks requests to a DIFFERENT origin by default: // Origin = protocol + domain + port // https://myapp.com → https://api.otherdomain.com ← BLOCKED // Server opt-in: Access-Control-Allow-Origin: *
Answer
Cross-Origin Resource Sharing — a browser security mechanism. By default, browsers block AJAX/fetch requests to a different origin. Servers must explicitly allow cross-origin access via CORS headers.
💡 CORS is enforced by the BROWSER, not the server. The server just signals what it allows. A Node.js script can fetch any URL — it has no CORS restriction.

What is the scope of let?
if (true) { let message = "Hello"; console.log(message); // "Hello" — fine inside block } console.log(message); // ReferenceError — outside block // vs var — leaks out: if (true) { var x = 10; } console.log(x); // 10 — var escapes the block
Answer: Block scoped
let is block-scoped — confined to the nearest {}. Access outside throws a ReferenceError. This is what var should have done from the start.

What is localStorage?

Why does (0.1 + 0.2) === 0.3 return false, and what's the correct way to compare floating-point numbers?
// Step 1 — the classic trap console.log((0.1 + 0.2) === 0.3); // false — IEEE 754 // Step 2 — toFixed() looks right but returns a STRING console.log((0.1 + 0.2).toFixed(2) === 0.3); // false — "0.30" !== 0.3 // Step 3 — correct: wrap in Number() so comparison is numeric console.log(Number((0.1 + 0.2).toFixed(2)) === 0.3); // true ✓ // Alternative — epsilon comparison (no string round-trip) console.log(Math.abs((0.1 + 0.2) - 0.3) < Number.EPSILON); // true ✓
Answer — IEEE 754 & the toFixed() String Trap
JavaScript stores decimals as IEEE 754 double-precision floats. 0.1 + 0.2 is actually 0.30000000000000004 in memory — close, but not 0.3.

The two-step trap: .toFixed(2) rounds the display to "0.30" — but it returns a string, not a number. Comparing a string to a number with === is always false.

Fix 1 — Number() + toFixed(): Number((0.1 + 0.2).toFixed(2)) === 0.3. Mind the parens: toFixed() must be called on the float result before Number() wraps it.

Fix 2 — epsilon comparison: Math.abs(a - b) < Number.EPSILON checks whether the difference is smaller than the tiniest float gap near 1. No string round-trip. But Number.EPSILON is a fixed size, so it only works for numbers around 1: 1000.1 + 1000.2 vs 2000.3 is off by ~2e-13 and fails the test. For bigger numbers, scale it: Math.abs(a - b) < Number.EPSILON * Math.max(Math.abs(a), Math.abs(b)), or pick a tolerance that fits the job (e.g. 0.001 for money in dollars).
💣 Paren Trap
console.log(Number(0.1 + 0.2).toFixed(2)) === 0.3) — the === ends up outside the console.log() call: syntax error. Always: Number((0.1 + 0.2).toFixed(2)) with inner parens forcing float addition first.
💡 0.1 + 0.2 in binary is like writing ⅓ in decimal — it never terminates exactly. IEEE 754 gives you ~15 significant digits of precision, plenty for most work, but not for naive equality checks.

Inside an async function with try/catch, how do you know if an awaited promise was fulfilled or rejected?

Answer: "Caught: Failed"
await is the switch. You don't query the promise: if execution reaches the line after the await, it was fulfilled and the variable holds the value. If it was rejected, the await line throws and control jumps to catch, where error holds the rejection reason. The try/catch is the test.

The twist: asyncFunc() itself comes back fulfilled with "Caught: Failed". Returning a value from catch marks the rejection as handled, so the outside world sees success. Re-throw if the caller needs to know, or use Promise.allSettled to get a { status, value / reason } report for each promise without one failure stopping the rest.
💡 Promise.reject("Failed") is a quiz shortcut: a promise that has already failed before you await it. In real code the promise comes from work still in progress (fetch, a timer, a file read), and that work decides fulfilled or rejected when it finishes.
💡 Uplink model: you send the request and stay on the line. The far end replies "carrier up" (fulfilled, with the data) or "link failed" (rejected, with the reason). await is you waiting for one of those two replies.
💣 JS Landmine
A catch that returns a value swallows the error: the caller's .catch() never fires. Pair with Q79, the try/catch that can't catch (setTimeout callback); this one can, because await keeps the function paused inside the try.

How do a Map, a plain object and an array of pairs look in the console, and which brackets go where?
// BUILD a Map: square brackets, an array of [key, value] pairs const map = new Map( [ [ "a", 1 ], [ "b", 2 ] ] ); console.log( map ); // Map(2) { 'a' => 1, 'b' => 2 } ← curly braces, arrows, size up front const obj = { a: 1, b: 2 }; console.log( obj ); // { a: 1, b: 2 } ← curly braces, colons console.log( [ ...map ] ); // [ [ 'a', 1 ], [ 'b', 2 ] ] ← array of pairs console.log( Object.fromEntries( map ) ); // { a: 1, b: 2 } Map → object new Map( Object.entries( obj ) ); // object → Map // ❌ [ a: 1, b: 2 ] is not valid anywhere: SyntaxError
Answer
You build a Map from square-bracket [key, value] pairs, but the console displays it in curly braces with => arrows and the size in front: Map(2) { 'a' => 1, 'b' => 2 }. A plain object shows colons: { a: 1, b: 2 }. Spreading a Map ([...map]) or calling Object.entries(obj) gives an array of pairs: [ [ 'a', 1 ], [ 'b', 2 ] ].
💡 Console ID guide: colon → plain object · arrow + size → Map · nested square brackets → array of pairs. Object.entries() and Object.fromEntries() convert between the forms.
💡 Object or Map? Neither is "more idiomatic"; they do different jobs. If you'd type the keys yourself in the code (a record, a config, JSON) → object. If the keys come from data at runtime, aren't strings, or get added and removed a lot, or you need .size → Map. See Q17 for the full comparison.
💣 JS Landmine
JSON.stringify( map ) gives "{}": a Map's entries aren't properties, so they're silently dropped. Convert first: JSON.stringify( Object.fromEntries( map ) ).

SOLID Principles — Breakdown

S Single Responsibility Principle
A function, class or module should do one job and have only one reason to change.
// ❌ one function deals, scores AND draws the screen function playHand() { /* deal + score + render */ } // ✅ one job each function dealCard() { /* ... */ } function scoreHand( hand ) { /* ... */ } function renderHand( hand ) { /* ... */ }
O Open-Closed Principle
Code should be open for extension, closed for modification. Add new behavior by adding code, not by editing working code.
// ✅ new payout? add a row, don't touch the logic const payouts = { blackjack: 1.5, win: 1, push: 0 }; function pay( result, bet ) { return bet * payouts[ result ]; }
L Liskov Substitution Principle
A subclass must be usable anywhere its parent is used, without breaking anything. If it swaps in and surprises the caller, the design is wrong.
class Bird { move() { return "flies"; } } class Penguin extends Bird { move() { throw new Error( "can't fly" ); } // ❌ breaks callers } // ✅ fix: Penguin's move() returns "swims", same contract
I Interface Segregation Principle
Don't force code to depend on methods it doesn't use. Many small, focused interfaces beat one giant one.
// ❌ every player object must have deal(), shuffle(), payout() // ✅ split by role: the Dealer gets deal/shuffle, // the Player only needs hit/stand
D Dependency Inversion Principle
High-level code should depend on abstractions, not on specific low-level details. In JS this usually means passing dependencies in instead of hard-coding them.
// ❌ hard-wired to localStorage function saveBalance( bal ) { localStorage.setItem( "bal", bal ); } // ✅ storage is passed in — swap for a test fake or a server function saveBalance( bal, storage ) { storage.save( "bal", bal ); }
💡 Interview one-liner: "SOLID keeps code easy to change. Each piece does one job, grows without being rewritten, swaps cleanly, asks only for what it needs, and gets its dependencies handed to it."

Tracing this — Find the Call Site

0 Inside an arrow function?
Arrows have no this of their own. Go out to the nearest enclosing regular function (or the top level) and run the checklist on that function instead.
1 Find the parentheses that run it
